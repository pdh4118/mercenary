# 3D 에셋 제작 인수인계 (PC의 Blender 세션용)

이 문서는 게임 코드를 만지는 클라우드 세션과 별개로, 사용자 PC(RTX 3070)에서 Blender로 3D 에셋을 만드는 세션을 위한 안내다.
이 세션은 **게임 코드·changelog를 건드리지 않는다**(저장소 CLAUDE.md의 changelog 규칙은 게임 코드 변경에만 해당). 산출물은 PNG와 Blender 스크립트다.

## 목표
유닛 그림을 방향·동작마다 일관되게 만든다. 3D 모델 하나를 포즈만 바꿔 렌더하면 방향·동작이 달라도 같은 캐릭터로 보인다.
게임은 이미 방향별 그림을 고르는 코드를 갖고 있다(`client/src/dirsprite.ts`, 주소에 `?dir3d=1`). 그림만 채우면 된다.

## 출력 규격 (게임 코드가 이 이름·구성을 그대로 읽는다)
- 파일명: `<병종>_<ally|enemy>_<방향>_<동작>_<번호>.png` 예) `spear_ally_2_walk_3.png`
- 방향 0 뒤 / 1 뒤 비스듬 / 2 옆 / 3 앞 비스듬 / 4 앞. 5방향만 렌더하고 나머지 3방향은 게임에서 좌우반전한다. 옆 방향은 **오른쪽을 보게** 그린다.
- 동작: idle 1컷(`idle_0`), walk 4컷(`walk_0~3`, 한 걸음 주기), attack 4컷(`attack_0~3`, 준비 → 타격 → 복귀 순서)
- 한 병종 = 5방향 × (1+4+4) × 아군/적 2팀 = 90장
- 256px 정사각, 배경 투명, 정사영 카메라 고도 24°, 외곽선 있는 툰 셰이딩, 조명 일정
- 발 위치(바닥 기준점)가 모든 컷에서 같아야 한다. 걸을 때 몸이 위아래로 튀는 건 괜찮지만 기준점이 옮겨 가면 안 된다.
- 아군은 초록 계열, 적은 회색·검정+붉은 포인트(기존 도트 그림 팔레트와 맞출 것)
- 결과물은 게임 저장소 `client/public/assets/units3d/`에 둔다. 기존 에셋은 지우지 않는다.

## 이미 있는 것
- `tools/blender/spear_pilot.py`: 도형을 조합한 치비 창병 파일럿(약 250줄). `bpy`로 돌린다. 사용법은 파일 맨 위 설명 참고.
  ONLY_DIRS 환경변수로 일부 방향만 렌더할 수 있다. 결과는 단순한 도형 모델이라 품질이 부족하다. 이게 개선 대상이다.
- `client/public/assets/units3d/spear_*`: 그 스크립트로 렌더한 90장(시험용).
- `client/public/assets/units/`: 현재 쓰는 2D 유닛 그림. **크기·화풍의 기준**이다(창병 109x88, 게임에서 0.5배로 표시).
  3D 그림이 이 그림 옆에 놓여도 어색하지 않게 비슷한 화풍(외곽선, 채도, 머리 큰 치비 비율)으로 만든다.
- 병종: 창병(spear), 궁수(archer), 기병(cavalry), 방패병(shield), 둔기병(mace), 검병(sword), 마법사(mage). 창병부터 한다.

## 작업 순서
1. 파일럿 결과를 먼저 보고 부족한 점(비율, 질감, 얼굴, 장비 디테일)을 정한다. 필요하면 Blender에서 직접 모델링하거나, 무료 모델을 가져와 쓴다(라이선스 확인, 출처를 문서에 적을 것).
2. 모델을 개선하고 5방향 × 동작을 렌더한다. GPU 렌더(Cycles/OptiX)를 쓰고 샘플은 충분히 높인다.
3. **렌더 결과를 직접 눈으로 본다.** 기존 2D 그림과 나란히 놓은 비교 이미지를 만들어 크기·화풍·기준점을 확인하고, 문제가 있으면 고친다.
4. 스크립트는 `tools/blender/`에 병종별로 저장해 같은 결과를 다시 만들 수 있게 한다.
5. 사용자에게 비교 이미지와 함께 보고한다. 모델을 개선한 점과 아직 부족한 점을 솔직하게 적는다.

## 하지 말 것
- 코드 꼼수로 그림을 만들어 내지 않는다(예: 2D 그림을 변형해 방향을 흉내). 모델링이나 가져온 모델로만 만든다.
- 기존 에셋을 덮어쓰거나 지우지 않는다.
- 파일 규격(이름, 컷 수, 방향 순서)을 바꾸지 않는다. 바꿔야 하면 사용자에게 먼저 묻는다.
