# Mercenary (머서너리)

용병을 고용해 주변에 배치하며 싸우는 뱀서류 멀티플레이(6인 이상) 게임.

## 구조

- `shared/` - 서버·클라이언트가 함께 쓰는 규칙과 프로토콜 (TypeScript)
- `server/` - 전투를 계산하는 권위 서버 (Node.js + ws, 초당 20틱)
- `client/` - 화면과 입력 (PixiJS + Vite). 입력만 보내고 서버 결과를 그린다

## 실행

```sh
npm install
npm run dev:server   # ws://localhost:8080
npm run dev:client   # http://localhost:5173
```

접속하면 로비가 나온다. 같은 서버에 여러 탭으로 접속하면 멀티플레이를 확인할 수 있다.
서버 주소는 `?server=ws://호스트:포트`, 서버 포트는 환경 변수 `PORT`(기본 8080)로 지정한다.
`?name=이름`을 붙여 열면 로비를 건너뛰고 바로 빠른 시작하고, `?name=이름&room=코드`면 그 방에 바로 참가한다(링크 공유·테스트용).
조작: WASD/방향키 이동, 마우스로 조준, 마우스 왼쪽 버튼(또는 스페이스)을 누르고 있으면 발사, 우클릭은 기병 돌격 지시, 캠프 근처에서 1~3 키로 용병 고용·Shift+1~5로 해고, 레벨업 카드는 Z/X/C, 무기 전환은 Q 또는 마우스 휠.

## 규칙 요약

- **적의 공격은 모션이 있다.** 닿는다고 피해를 입지 않고, 공격 예비 동작(빨간 부채꼴/선 표시)이 끝나는 순간 그 범위 안에 있으면 맞는다. 피하면 안 맞는다.
- **병종 5종**(기병·창병·궁병·검방병·둔기병)은 적과 용병 모두 같다. 상성은 기병<창병<궁병<검방병<둔기병(왼쪽이 오른쪽에게 약함)이고, 기병은 창병 말고는 전부에게 강하다. 배율은 `shared/src/rules.ts`의 `COUNTER_MATRIX`.
- **용병**은 주인공 주변 진형 자리(앞줄 검방·둔기 / 중간 창 / 뒷줄 궁 / 기병은 양옆 날개)를 따라다니며 자동으로 싸운다. 각자 체력이 있고, 쓰러지면 부활한다(기병 25초, 나머지 15초).
- **통솔력**: 용병마다 비용(기병 2, 나머지 1)이 있고, 보유 용병의 비용 합이 통솔력(시작 5)을 넘을 수 없다. 늘리는 방법은 레벨업 선택지(예정).
- **캠프**가 무작위로 생기고, 적을 잡아 모은 금화로 용병을 고용한다(보유 수가 늘수록 비싸짐). 캠프에서는 해고도 되고 지불한 금화의 절반을 돌려받는다.
- **기병**은 자신이 강한 적(특히 궁병)을 먼저 노려 옆·뒤로 돌아 들어가고, 창병 적은 피해 돌며, 공격한 뒤엔 잠깐 물러난다(치고 빠지기). 평소 활동 범위는 넓고, **우클릭으로 돌격 지점을 지시**하면 6초간 그 지점으로 나가 싸운다(체력이 낮으면 자동 복귀).

- **경험치와 레벨업**: 적을 잡으면 경험치의 50%는 처치한 사람(용병이 잡아도 주인)에게, 나머지 50%는 접속한 모든 플레이어에게 똑같이 나뉜다(뒤처져도 따라갈 수 있게). 레벨업하면 각자 화면에 카드 3장이 뜨고, **게임은 멈추지 않는다**. 키 한 번(Z/X/C)으로 고르고, 시간 제한이 없으며 여러 번 레벨업하면 쌓여서 차례로 뜬다. 카드는 규모(통솔력·고용 할인·전리품) / 용병 강화 / 주인공 강화에서 섞여 나오고, 가진 병종의 단련 카드만 나온다. 카드 목록은 `shared/src/cards.ts`.

- **주인공 무기**: 활(궁병계, 원거리) / 창(창병계, 긴 찌르기) / 검(검방병계, 넓고 빠른 휘두르기) / 철퇴(둔기병계, 느리고 강한 범위 타격). 무기마다 병종 속성이 있어 같은 상성표가 적용되므로, 적 병종에 맞춰 무기를 바꾸면 유리하다(화면 오른쪽 아래에 현재 무기의 유리/불리 병종이 표시된다). 무기를 바꾼 직후 0.25초는 공격할 수 없다.
- **레벨업 순간**에는 주변(240px) 적이 밀려나고 잠깐(0.8초) 공격하지 못한다. 카드를 고를 틈을 주기 위함.

## 방 관리

- **로비**: 방 목록(실시간 갱신), 빠른 시작(자리 있는 방 중 사람이 많은 곳, 없으면 새로 만듦), 방 만들기, 4글자 코드로 참가.
- 방마다 **독립된 판**이고 최대 8명, 서버 전체 방은 30개까지. 아무도 없는 방은 사라진다.
- **방장**은 처음 만든 사람이고, 다른 참가자를 내보낼 수 있다. 방장이 나가면 다음 사람에게 넘어간다. `Esc`로 방 메뉴(코드·참가자·내보내기·나가기)를 연다.
- **접속이 끊겨도 30초**는 자리를 지킨다. 그 안에 같은 브라우저 탭에서 다시 접속하면(새로고침 포함) 같은 캐릭터·용병·금화로 이어서 한다. 기다리는 동안 주인공은 제자리에 서고 적의 목표가 되지 않으며, 용병은 계속 싸운다. 30초가 지나면 방에서 빠진다.
- 서버는 메시지 크기(2KB)와 빈도(초당 120회)를 제한하고, 응답 없는 연결은 주기적으로 확인해 정리한다. 방 로직은 `server/src/rooms.ts`.

## 밸런스 점검

`npm run balance -w server -- <초> <인원 목록> <시드 수>` (예: `-- 300 1,3,6 3`). 봇이 플레이하는 판을 서버 로직 그대로 돌려 주인공·용병 사망, 레벨, 적 수 추이를 뽑는다. `DETAIL=1`을 붙이면 병종별 쓰러짐도 나온다. 수치를 바꾼 뒤 이걸로 확인한다.

## 에셋

병종 스프라이트(아군·적 각 5종)는 `client/public/assets/units/`에 있다. 스프라이트 시트를 한 장씩 자르는 도구는 `tools/slice_sheet.py`(사용법은 파일 머리말).

이미지·소리 생성 AI나 아티스트에게 의뢰할 때 쓰는 프롬프트: [`docs/asset-prompts.md`](docs/asset-prompts.md)

## 현재 상태

프로토타입 7단계: 적 병종과 공격 모션, 용병 고용·진형·상성, 캠프, 통솔력·해고, 기병 운용과 우클릭 돌격, 경험치 공유와 레벨업 카드, 주인공 무기 변경, 임시 밸런스, 병종 스프라이트, 방 관리(로비·방장·재접속).
수치(체력·피해·가격·스폰량·경험치)는 임시값이다. 봇 시뮬레이션으로 1차 조정만 했고 실제 플레이로 다듬어야 한다.

다음: 실제 플레이로 밸런스 조정, 주인공·캠프·바닥·카드 아이콘 에셋 교체, 효과음, 서버 배포.
